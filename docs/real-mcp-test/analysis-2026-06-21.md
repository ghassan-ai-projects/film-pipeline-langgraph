## Issues Found

### Issue 1: Response Field Name Inconsistency (MINOR)

**Tool:** `get_current_phase` vs `approve_phase`/`approve_intake`

| Tool | Field name |
|------|-----------|
| `get_current_phase` | `phase` |
| `approve_phase` | `current_phase` |
| `approve_intake` | `current_phase` |
| `get_orchestrator_summary` | `current_phase` |

The operator guide uses `current_phase` in example responses but `get_current_phase`
returns `phase`. This is a minor naming inconsistency — both work, but callers
must handle both keys.

**Status:** ✅ FIXED — `get_current_phase` now returns `current_phase` key (consistent with
`approve_phase`, `approve_intake`, `get_orchestrator_summary`).
Changed in `src/film_pipeline/mcp/tools/__init__.py` line 328:
`_ok(phase=...)` → `_ok(current_phase=...)`.
Updated `tests/smoke/test_operator_workflow.py` to match.

### Issue 2: inspect_artifact Uses `content` Not `data` (DOCS)

The operator guide doesn't document `inspect_artifact` response shape. The artifact
payload is under the `content` key, not `data`.

**Response shape:**
```json
{
  "ok": true,
  "content": { /* artifact payload as dict */ }
}
```

**Status:** Documentation gap. Add to operator guide.

### Issue 3: list_artifacts Field Names Not Documented (DOCS)

| Actual field | Description |
|-------------|-------------|
| `artifact_id` | Unique artifact identifier |
| `artifact_type` | Schema type (film_constitution, script, etc.) |
| `phase` | Creation phase |
| `version` | Integer version |
| `status` | "candidate" or "approved" |

The operator guide doesn't document this response shape. Add to guide.

### Issue 4: `list_profiles` Uses `total` Not `profile_count` (DOCS)

Response: `{"ok": true, "total": 12, "profiles": [...]}`

The operator guide doesn't document the response shape for this tool.

### Non-Issue: `list_profiles` Returns 12 Profiles

12 `.yaml` profile files exist under `profiles/` and are correctly discovered.

### Non-Issue: Artifacts with Wrong `artifact_type`

Some artifacts have `artifact_type` values that don't match their content:
- `reference_index` has `artifact_type: "script"` — should be `"reference_index"` or `"visual_dev"`
- `story_bible` has `artifact_type: "script"` — should be `"story_bible"` or `"script"`

This is because the artifact type is derived from the phase, not the content.
Belongs to a different fix (artifact type tagging).
